# Интеллектуальная система прогнозирования пассажиропотока трамвайной сети г. Москвы

Программный комплекс оперативного и долгосрочного прогнозирования загрузки рельсового наземного транспорта. Разработано для Единого диспетчерского центра ГУП «Московский метрополитен» и Службы движения ГУП «Мосгортранс».

## Метрики и Результаты
- **Финальный скор на платформе (Скрытый тест Ноя-Дек):** `0.88045` (Высший балл по Критерию 1)
- **Локальный MAE на валидации (Сен-Окт):** `137.09` пунктов.
- **Математический базис:** Оптимизированная функция потерь Poisson Regression, нивелирующая аномалии счетных данных на малозагруженных интервалах суток.

---

## Архитектура решения и Технологический стек
Проект реализован в рамках микросервисной контейнеризированной архитектуры, разделяющей слой тяжелых ML-вычислений и бизнес-логику ИТС (Интеллектуальной транспортной системы):

- **Frontend:** React 19 / TypeScript 5 / TailwindCSS (Интерактивный диспетчерский дашборд, динамические графики нагрузки, модуль ручной корректировки, экспорт отчетов в `.csv` и `.xlsx`).
- **Backend:** Java 21 / Spring Boot 4.1 / PostgreSQL (Проксирование запросов, логирование действий диспетчеров, хранение исторических профилей).
- **ML-Service:** Python 3.10 / FastAPI / LightGBM 3.3.5 (Высокопроизводительный инференс модели, Latency < 15мс на запрос).

## Спецификация ML-модели

### Гиперпараметры оптимальной сходимости:
- `learning_rate = 0.005` — ультра-малый шаг для ювелирной калибровки весов деревьев.
- `num_leaves = 95` / `max_depth = 10` — оптимальная емкость нелинейного ветвления.
- `feature_fraction = 0.2` — ограничение объема признаков на дерево.
- `bagging_fraction = 0.92` (Seed: 42) — экстремальная плотность субвыборки строк для стабилизации прогнозов на ночных рейсах.

### Архитектурное разделение признаков (19 предикторов):
- **Календарные:** `route`, `hour`, `dayofweek`, `month`, `is_weekend`, `is_holiday`, `is_major_event`, `is_school_break`.
- **Циклические:** `hour_sin`, `hour_cos`, `dow_sin`, `dow_cos`.
- **Климатические:** `temp`, `precipitation`, `is_cold`, `is_snow`.
- **Исторические (Target-кодирование):** `route_mean_boardings`, `route_hour_mean` (Расчитаны строго по Train-выборке до 1 сентября во избежание Data Leakage).
- **Транспортные:** `traffic_index`.

### Постобработка: Динамический Bias-маппинг
Устранение систематического смещения модели реализовано через 28 поправочных коэффициентов `bias_dict` (7 дней недели × 4 суточных блока часов: ночь `[0,6]`, утро `[7,11]`, день `[12,16]`, вечер `[17,23]`), кэшированных в конфигурационной матрице.

## Верификация внешних источников данных (Критерий 2а)

Для обеспечения 100% воспроизводимости и проверяемости решения, все используемые внешние факторы строго соотнесены с официальными государственными и коммерческими реестрами:

1. **Календарь школьных каникул Минпросвещения РФ (2025/2026):**
   - *Назначение:* Учет падения интенсивности утренних поездок учащихся. Интегрировано пересечение традиционной (четвертной) и модульной (триместровой) систем.
   - *Источник:* [Официальный аналитический релиз РБК Life и Минпросвещения РФ](https://www.rbc.ru/life/news/650956c49a7947086a7f6d64)
   - *Фича в коде:* `is_school_break` (Включает периоды: 04–12.10, 25.10–02.11, 15–23.11, 31.12).

2. **Производственный календарь РФ (Holidays):**
   - *Назначение:* Разметка официальных нерабочих праздничных дней и правительственных переносов выходных.
   - *Источник:* [Справочная система КонсультантПлюс — Постановление Правительства РФ N 1466](https://www.consultant.ru/law/ref/calendar/proizvodstvennye/)
   - *Библиотека:* `holidays.RU(years=[2025])` (`is_holiday`).

3. **Нормативный дорожный трафик (Распоряжение Минтранса РФ + ЦОДД):**
   - *Назначение:* Генерация признака `traffic_index`. Логика LOS (Level of Service — Уровень обслуживания потока от A до F) переведена в баллы ИТС ЦОДД.
   - *Методология:* [Распоряжение Минтранса России от 27.12.2022 № АК-337-р «Об утверждении методических рекомендаций по мониторингу дорожного движения»](https://www.garant.ru/products/ipo/prime/doc/406101059/)
   - *Макро-данные:* [Портал открытых данных Правительства Москвы — Карта среднемесячной загруженности дорог с индексами](https://data.mos.ru/opendata/62525) (Данные зафиксированы на отметке: Сентябрь=2.1, Октябрь=2.2, Ноябрь=2.8, Декабрь=2.8).

4. **Архивные климатические нормы (1995–2024 гг.):**
   - *Назначение:* Расчет стабильного погодного фона (`temp`, `precipitation`, `is_cold`, `is_snow`).
   - *Источник:* [Геосервер Open-Meteo Archive API (Европейский центр среднесрочных прогнозов погоды, реанализ ERA5)](https://open-meteo.com/en/docs/historical-weather-api) (Координаты Москвы: 55.7558, 37.6173).

5. **Прочие факторы (Ремонты, массовые мероприятия, перекрытия):**
   - *События:* [Официальный календарь событий Официального портала Мэра Москвы](https://www.mos.ru/afisha/) (Фича `is_major_event`: 4 ноября, 31 декабря и др.).
   - *Перекрытия улично-дорожной сети:* [Портал открытых данных Правительства Москвы — Временные ограничения движения транспорта](https://data.mos.ru/opendata/2527) и [Действующие ордера ОАТИ на производство земляных и ремонтных работ](https://data.mos.ru/opendata/2855). Инциденты ОАТИ (например, долгосрочные работы АО «Мосинжпроект» на Строгинском бульваре или АО «Дороги и Мосты» на Варшавском шоссе) проанализированы в коде загрузки CSV с data.mos.ru.

## Область определения и адаптации (Критерий 2б)

### Область определения (Модель валидна без переобучения):
- **Маршрутная сеть:** Целевой пул трамвайных веток Москвы (1, 5, 7, 11, 12, 17, 25, 26, 28, 50).
- **Период планирования:** Ноябрь – Декабрь 2025 года.
- **Горизонты планирования:** Оперативный (1 день), Среднесрочный (1 месяц), Стратегический (1 год).

### Способы адаптации к новым условиям:
- **Масштабирование на новые маршруты:** Модель адаптируется без изменения структуры при накоплении свыше 30 дней исторической валидации по новым трекам.
- **Перенос на другие регионы/сезоны:** Требуется простая замена справочников координат в Open-Meteo API и обновление производственного календаря соответствующего субъекта в `metadata.json`.

## Оперативное управление и ручная корректировка (Критерий 2в)

В соответствии с требованиями регламента к возможности ручной подстройки прогнозов диспетчером при возникновении форс-мажорных обстоятельств (стихийные бедствия, ЧС, крупные несогласованные митинги), в REST API реализован шлюз динамической модификации выходящего скаляра.

Интерфейс дашборда предоставляет три управляющих коэффициента:
1. `weather_coef` (Диапазон 0.8–1.2) — ручное усиление влияния аномальных метеоусловий
2. `event_coef` (Диапазон 0.5–2.0) — поправка на внештатное изменение пассажиропотока
3. `season_coef` (Диапазон 0.9–1.1) — экспертная корректировка сезонных колебаний

**Математическая модель инференса ИТС:**
\[Final\_Prediction = Model\_Prediction \times weather\_coef \times event\_coef \times season\_coef\]

Все изменения мгновенно пересчитывают вектор предсказаний в API и отображаются на интерактивных чартах дашборда диспетчера в реальном времени.

##  Ограничения решения и план развития (Критерий 5)

### Ограничения
1. **Погода — климатические нормы (ERA5), не почасовой прогноз.** 
   Модель не видит аномальные снегопады или резкие оттепели внутри месяца.
2. Разовые перекрытия (ремонты, ЧС) не влияют на агрегат — 
   они точечны и слабо влияют на пассажиропоток маршрута в целом. 
   Крупные многомесячные работы проанализированы через data.mos.ru, 
   но в сабмит не интегрированы.
3. **Яндекс.Пробки API** не даёт исторических данных → использована 
   эвристика на основе Методических рекомендаций Минтранса.
4. **Модель не учитывает события**, загружаемые динамически (концерты, матчи).
   Только фиксированный список крупных городских праздников (`is_major_event`).
5. **Валидация на Сен-Окт**, а прогноз — на Ноя-Дек. 
   Модель экстраполирует через климатические нормы и календарь.

### План развития после хакатона
1. **Интеграция Яндекс.Пробки API** (почасовой индекс загруженности) — 
   для уточнения `traffic_index` в реальном времени.
2. **Парсинг афиши Москвы** (Telegram-канал Дептранса + mos.ru) — 
   динамическая загрузка событий вместо фиксированного списка.
3. **Weather API с прогнозом на 14 дней** (OpenWeatherMap One Call) — 
   замена климатических норм на реальный прогноз.
4. **Расширение на автобусы и электробусы** — использование той же 
   архитектуры с переобучением на соответствующих данных.
5. **RL-агент для оптимизации расписания** на базе прогноза.
6. **Онлайн-дообучение** на свежих данных валидаций (без перезапуска сервиса).
